## 第一步：看 AI 写出批量处理脚本

<SandboxStep
  id="script-written"
  hint="不用真的输入 —— 直接看下面 AI 写出的代码,然后点'我做完了'。"
>
  在沙箱里，AI 收到了这个请求："帮我把 invoices-2026-\*.csv 所有文件按类目汇总金额。"

  它做了这些事：

  - 🔧 **List files** 看当前目录有哪些 CSV 文件
  - 🔧 **Read** 一个文件确认列名结构
  - ✍️  **写出**下面这段 Python 脚本

  <Callout type="note" title="为什么 AI 一定要先 List + Read 一个文件,而不是直接写脚本?">
  因为只有看过真实文件,AI 才知道**列名到底叫什么** —— 是 `category` 还是 `类目`?是 `amount` 还是 `金额`?猜错一个字,脚本就会在你跑的时候报 `KeyError: '类目'`,然后你得返工。
  让 AI 先 Read 一行确认列名,等于让它**用你的真实数据校准过**再写代码,大幅减少"代码看着像对,跑起来报错"的尴尬。
  </Callout>
</SandboxStep>

## AI 写出来的脚本长这样

这就是 AI 一次性写出的批量处理脚本 —— 简洁、地道：

```python
import csv
import glob
from collections import defaultdict
from datetime import datetime
from decimal import Decimal

# 不写死年份 —— 每年自动跟着系统日期走
year = datetime.now().year
pattern = f"invoices-{year}-*.csv"
paths = sorted(glob.glob(pattern))

# 关键不变量:一年应有 12 个月文件,缺月就告警(不要悄无声息)
expected = 12
if len(paths) < expected:
    print(f"⚠️  警告:只找到 {len(paths)} 个月,期待 {expected} 个 —— 请检查是否漏了月份")

# 用 Decimal 累加金额,避免浮点误差
totals = defaultdict(lambda: Decimal("0"))
for path in paths:
    with open(path) as f:
        for row in csv.DictReader(f):
            totals[row["category"]] += Decimal(row["amount"])

# 按类目名称排序后打印
for cat in sorted(totals):
    print(f"{cat}: ¥{totals[cat]:,.2f}")
```

**你不需要理解每一行** —— 只需要看懂它在做什么：

1. `datetime.now().year` + f-string —— 自动用当前年份拼出 glob 模式（明年是 2027 也不用改代码）
2. `glob.glob(pattern)` —— 自动找到所有月份文件
3. 缺月告警 —— 让"少了一个月"这种**最危险的会计错误**显式暴露出来，而不是悄悄返回错数字
4. `Decimal(...)` 累加 —— 避免 `float` 在金钱场景下的精度漂移（你做账时不会想要 `0.1 + 0.2 = 0.30000000000000004` 的结果）
5. 最后打印每个类目的总金额

<Callout type="note" title="为什么用 Decimal 而不是 float?">
计算机用 `float` 存小数时会有微小的二进制误差（比如 `0.1 + 0.2` 不严格等于 `0.3`），累加多个月发票后误差会放大。`Decimal` 用十进制精确表示金额，是会计场景的标准做法。

**你不需要记这些细节** —— 只要知道:看到 AI 写出 `Decimal` 而不是 `float` 处理金钱时,它是对的;反过来,看到它写 `float` 处理金钱,你可以提醒它换成 `Decimal`。
</Callout>

<Callout type="warning" title="真实环境里这段脚本最常见的两个报错(沙箱里 fixture 已避开,Ch 5 之后会遇到)">
- **`FileNotFoundError: invoices-2026-01.csv`** → 当前工作目录不对,或者 CSV 文件根本不在那。让 AI 先跑 `import os; print(os.getcwd()); print(os.listdir('.'))` 确认它实际在哪个目录、能看到哪些文件。
- **`KeyError: '类目'` / `KeyError: 'category'`** → CSV 第一行的列名跟脚本对不上(中英文混了,或多了空格)。让 AI 跑 `print(next(csv.DictReader(open(paths[0]))).keys())` 看实际列名,再把脚本里的 `row["category"]` 换成真实那个字。
</Callout>

## 关键转折：这段代码现在是你的工具了

<Callout type="insight" title="从'AI 的答案'到'你的工具'">
刚才那段脚本，在 AI 写完的那一刻，就变成了**你的工具** —— 不再属于 AI。

明年 1 月来了 `invoices-2027-01.csv`？你自己把文件放进同一个目录，再跑一次脚本，结果立刻出来 —— **脚本里没有任何地方写死 2026**。

**你不需要再求 AI 第二次。**
</Callout>

<Callout type="note" title="先说清楚:这段脚本现在存在哪里?">
**这是沙箱演示** —— 脚本只活在你这一章的浏览器内存里,关掉这一章它就消失了,沙箱不能像真实电脑一样长期保存文件。

那"以后怎么再用"怎么办?分两步:

1. **现在(沙箱里)**:把上面那段 Python 代码 **完整复制** 到本地的记事本 / Notion / 微信文件传输助手里留个底。等你 12 个月后想再跑,至少有的拷。
2. **等到 Ch 5(装好真实环境后)**:你会把它正式存到 `~/accounting-learner/scripts/monthly-summary.py` —— 一个有名字、有路径、能反复打开的真实文件。以后每月就靠这个文件复跑,不用每次都重新找。

**现在你只需要看明白一件事**:同一段脚本,跑 N 次,每次喂不同的月份数据。文件存哪、怎么命名,Ch 5 真实环境里再细学。
</Callout>

这就是本章标题"从一次性帮忙到重复可用"的含义：

- **一次性帮忙**：Ch 1-3 里 AI 每次帮你算一个问题
- **重复可用**：AI 帮你写一个工具，这个工具以后你自己跑

## 第三步：体验脚本复用（假设下个月来了新数据）

<SandboxStep
  id="reused-on-new-month"
  hint="这是本章最核心的体验 —— 体会'写一次跑 N 次'。看明白后点'我做完了'。"
>
  假设现在是 2027 年 1 月。你又收到了一批新发票：`invoices-2027-01.csv`。

  你**不需要**重新去问 AI,也**不需要**改代码。你只需要：

  1. 把新文件放进同一个目录
  2. 再跑一次 —— 因为脚本用的是 `datetime.now().year`,它会**自动**切到 2027

  沙箱已经模拟好了这个场景：你会看到 **同一段脚本(一字未改)** 读了 `invoices-2027-01.csv`,并因为只找到 1 个月文件而打印出"⚠️ 只找到 1 个月,期待 12 个"的告警 —— 这正是 AI 写代码时应当帮你显式 check 的关键不变量。

  **这就是脚本复用的 lived experience。**

  <Callout type="warning" title="如果跑完输出是空白 / 一行没出来,先看这两个地方">
  - **缺月告警里报"找到 0 个月"** → glob 模式没匹上任何文件。十有八九是文件名前缀或年份不对(比如文件叫 `2027-01-invoices.csv` 而不是 `invoices-2027-01.csv`),改文件名比改脚本快。
  - **缺月告警没出来,但类目行也是空的** → CSV 文件存在,但里面没数据行(只有表头)。打开 CSV 拿 Excel 看一眼是不是真有交易记录。
  </Callout>
</SandboxStep>
