## AI 写出来的代码长这样

这是 AI 会生成的那段 Python 脚本——简洁、地道，只有 10 行：

```python
import csv
from collections import defaultdict

totals = defaultdict(float)
with open("invoices.csv", encoding="utf-8") as f:
    for row in csv.DictReader(f):
        totals[row["category"]] += float(row["amount"])

for cat in sorted(totals):
    print(f"{cat}: ¥{totals[cat]:.2f}")
```

你不需要理解这段代码的每一行——你只需要知道它在做什么：

1. 打开 `invoices.csv`（明确告诉它"按 UTF-8 解码"）
2. 对每一行：把 `amount` 加到对应 `category` 的累计里
3. 最后按类目名字排序，打印每个类目的总金额

<Callout type="warn" title="为什么 open() 一定要写 encoding=&quot;utf-8&quot;">
**`encoding="utf-8"` 是地道代码该有的写法。** 在 macOS 上不加也能跑（默认就是 utf-8），但同样这段脚本在 Windows 上不加会直接 `UnicodeDecodeError`（默认 cp936/GBK，遇到 utf-8 编码的中文就崩）。

AI 写代码时这个细节经常漏 —— 它在训练数据里见过太多没带 encoding 的写法。**你要养成『见到 `open()` 就检查有没有 encoding』的习惯**，这是把"能跑"升级到"跨机器都能跑"的关键一行。
</Callout>

<Callout type="warn" title="为什么这里用 float、真实账上要用 Decimal">
**这里 `defaultdict(float)` 是给沙箱演示用 —— 真实会计场景应该用 `Decimal`。**

浮点数（float）按 IEEE 754 存储，`0.1 + 0.2` 不等于 `0.3`，几十行累加下来会偏一两分钱。课堂演示无所谓，但**会计账上差一分钱都不能合账**。

Ch 4 会专门讲：为什么财务要用 `Decimal`、怎么改这段脚本、改完之后误差从哪儿来的。现在你只要在脑子里挂个钩 —— "看到 AI 给我写 `float` 处理金额，要警惕"。
</Callout>

<Callout type="warn" title="真实数据不会这么干净">
你看到的 `invoices.csv` 是为教学准备过的干净数据：50 行、5 个类目、没有缺失、没有错乱。**真实从财务系统导出的 CSV 长得没这么乖**：

- **重复行**（同一笔被导出两次） → 上面这段脚本会傻乎乎算两遍
- **缺失值**（类目空白 `""`） → `defaultdict` 会默默给你建一个空字符串 `""` 的类目，金额都堆在那里
- **红字 / 退款**（金额是 `-150.00`） → AI 会照减回去 —— 算式没错，但你要确认"这张到底应不应该冲销"
- **金额带千分位逗号**（`1,250.00`） → `float()` 直接报 `ValueError: could not convert string to float`

这些情况脚本要么算错、要么直接崩。**Ch 14 的 capstone 项目会专门教你怎么让 AI 处理这些噪声 ——** 现在你只要在脑子里记住一句话：「**沙箱里跑通 ≠ 真实数据上也能跑通**」。
</Callout>

  沙箱已经帮你跑好了上面那段 Python 脚本。你会看到类似这样的输出：

  ```

  办公: ¥1,591.70
  差旅: ¥2,363.00
  通讯: ¥584.00
  餐饮: ¥4,311.40
  ```

  注意这一行提示：**这个数字不是 AI 编的 —— 是 Python 真跑出来的。**

  每一个数字都可以追溯：是哪几行发票加出来的，金额是否合理，都可以回到 `invoices.csv` 核查。

  看明白之后，点'我做完了'。
</SandboxStep>

<Callout type="warn" title="把这段脚本搬到自己电脑上,常见 4 种报错">
沙箱里跑得很顺，但同一段代码贴到你自己电脑上、对着真实导出的 CSV 跑，可能会撞到这几种错。不要慌，**报错的最后一行往往直接告诉你原因**，对照下面这张表就能修：

| 报错信息（最后一行） | 真实意思 | 怎么处理 |
| --- | --- | --- |
| `FileNotFoundError: 'invoices.csv'` | Python 是在**它当前所在的目录**找文件,没找到 | 先在终端 `cd` 到 CSV 所在的文件夹再跑；或者把脚本里的 `"invoices.csv"` 改成完整路径,比如 `"/Users/你/Downloads/invoices.csv"` |
| `KeyError: 'category'` | CSV 里没有叫 `category` 的列(可能叫"类目"、`Category`、`Cat`……) | 让 AI 帮你先 `print(list(reader.fieldnames))` 看真实列名是啥,再把脚本里的 `row["category"]` 改成对应名字 |
| `UnicodeDecodeError: 'gbk' codec can't decode...` | 你在 Windows / 中文 locale 上跑,没加 `encoding="utf-8"` | 回到上面那段代码,确认 `open(...)` 写了 `encoding="utf-8"` —— 这就是为什么本章特别强调这一行 |
| 跑完啥都不输出（0 行） | CSV 是空的,或者 `fieldnames` 拼错了导致每一行都被跳过 | 在循环里加一行 `print(row)` 看看到底读到啥；或在打开后 `print(sum(1 for _ in reader))` 看读到几行 |

**普适做法：把报错的最后一行原文直接贴回给 AI，让它帮你定位。** 你不需要自己读懂英文 stacktrace —— AI 读得懂,而且会用中文解释给你。这就是"AI 工具 vs Stack Overflow"的另一处差别。
</Callout>

## 关键认知

<Callout type="insight" title="三件独立的事,互相印证">
**AI 写代码 ≠ AI 跑代码 ≠ 你看结果**

这是三件分开的事：

1. **AI 写了代码** —— 它用语言能力生成了一段 Python
2. **沙箱跑了代码** —— Python 解释器真的执行了这段脚本，算出了数字
3. **你看到了结果** —— 那几行数字，是代码算的，不是 AI 记忆里的

三者互相印证：代码可以复查，结果可以追溯。这才是 AI 工具 vs ChatGPT 网页版的真正不同。
</Callout>

<Callout type="warn" title="重要边界:沙箱跑对了 ≠ 你判断对了">
沙箱替你跑代码，但它**不能替你判断结果的意义**。

`餐饮: ¥4,311.40` ——这个数字合理吗？和上个月比多了还是少了？有没有异常？

**AI 算的对，但意义还是你来确认。**

这是财务人员不可替代的判断能力。会用 AI 工具，是让这种判断更有数据支撑——而不是把判断也交给 AI。
</Callout>

|---|---|---|---|
