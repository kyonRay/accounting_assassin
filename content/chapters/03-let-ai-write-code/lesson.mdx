## AI 写出来的代码长这样

这是 AI 会生成的那段 Python 脚本——简洁、地道,只有 10 行:

```python
import csv
from collections import defaultdict

totals = defaultdict(float)
with open("invoices.csv") as f:
    for row in csv.DictReader(f):
        totals[row["category"]] += float(row["amount"])

for cat in sorted(totals):
    print(f"{cat}: ¥{totals[cat]:.2f}")
```

你不需要理解这段代码的每一行——你只需要知道它在做什么:

1. 打开 `invoices.csv`
2. 对每一行:把 `amount` 加到对应 `category` 的累计里
3. 最后按类目名字排序,打印每个类目的总金额

## 关键认知

<Callout type="insight" title="三件独立的事,互相印证">
**AI 写代码 ≠ AI 跑代码 ≠ 你看结果**

这是三件分开的事:

1. **AI 写了代码** —— 它用语言能力生成了一段 Python
2. **沙箱跑了代码** —— Python 解释器真的执行了这段脚本,算出了数字
3. **你看到了结果** —— 那几行数字,是代码算的,不是 AI 记忆里的

三者互相印证:代码可以复查,结果可以追溯。这才是 AI 工具 vs ChatGPT 网页版的真正不同。
</Callout>

<Callout type="warn" title="重要边界:沙箱跑对了 ≠ 你判断对了">
沙箱替你跑代码,但它**不能替你判断结果的意义**。

`餐饮: ¥4,311.40` ——这个数字合理吗?和上个月比多了还是少了?有没有异常?

**AI 算的对,但意义还是你来确认。**

这是财务人员不可替代的判断能力。会用 AI 工具,是让这种判断更有数据支撑——而不是把判断也交给 AI。
</Callout>

## 本章小结

| | AI 写代码 | 沙箱跑代码 | 你判断结果 |
|---|---|---|---|
| 谁来做 | AI(语言能力) | Python 解释器(计算能力) | 你(业务判断) |
| 能力来源 | 训练数据 + 上下文 | 确定性算法 | 10 年会计经验 |
| 可追溯吗 | ✓ 代码可复查 | ✓ 结果可复算 | ✓ 底稿可存档 |
