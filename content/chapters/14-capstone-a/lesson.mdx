## 2. 安装依赖：pandas 和 openpyxl

Ch 7 的 `invoice_ocr.py` 只用了标准库（subprocess、json、sys），不需要安装额外的包。但这次三个工具都要处理 Excel，需要用到两个第三方库：

- **pandas** — 处理表格数据（读 CSV、筛选、分组）
- **openpyxl** — 读写 `.xlsx` 文件（Excel 格式）


  ```bash
  python3 -c "import pandas; import openpyxl; print('OK')"
  ```

  看到 `OK` 就说明安装好了。

  ```bash
  pip3 install --user -i https://pypi.tuna.tsinghua.edu.cn/simple pandas openpyxl
  ```

  （只有第一次需要指定 `-i`；如果你想以后每次都默认走镜像，可以让 Claude 帮你写一份 `~/.pip/pip.conf`。）

  如果命令报 `pip3: command not found`：Ch 5 安装 Python 那一步没成功。回 Ch 5 重做，或者先跑 `which python3` 看一下 Python 是不是装在系统能找到的位置。
  </Callout>

  <Callout type="warn" title="Homebrew Python 报错？用这个备用命令">
  如果你的 Python 是通过 Homebrew 安装的（2026 年的 macOS 常见情况），`pip3 install --user` 可能会报错：
  ```
  error: externally-managed-environment
  ```

  ```bash

  ```
  这个选项告诉 pip「我知道在干什么，让我继续」，对学习场景完全没有问题。

  如果同时遇到下载慢，可以把上面的镜像参数 `-i https://pypi.tuna.tsinghua.edu.cn/simple` 一起加上。
  </Callout>

  <Callout type="tip" title="虚拟环境（venv）是什么？以后再讲">
  你可能在某些教程里见过 `python3 -m venv` 这样的命令。venv 是管理 Python 依赖的进阶方式，能避免不同项目之间的版本冲突。

## 3. 工具一：invoice-ocr · 批量发票 OCR + Excel 汇总

### 这个工具做什么？

Ch 7 你写了 `invoice_ocr.py`，它每次处理**一张**发票。

现在毕业作品 A 的第一个工具要升级这个能力：**一次处理一整个文件夹的发票**，把所有提取结果汇总到一个 Excel 文件里。

### 降级流：AI 工具不是万能的，设计降级路径才是真本领

在实际工作中，`aa-ocr` 不会每张发票都完美识别。回顾 Ch 7 的接口：

| 退出码 | 含义 |
|---|---|
| `0` | 全部字段提取成功 |
| `4` | 部分字段提取成功（某些字段值为 `null`） |
| `3` | 无法识别（图片质量太差或格式不支持） |
| `2` | 文件不存在或无法读取 |

一张清晰的 PDF 发票，退出码通常是 `0`；手机拍的模糊照片，可能是 `4` 甚至 `3`。

**工程师的应对方式不是抱怨 AI 不够完美，而是设计降级流（Fallback Flow）**：

```
aa-ocr 处理每张发票
  ↓
退出码 0  → 写入「主表」sheet（日期/商家/金额/税号）
退出码 4  → 写入「需手填」sheet（已提取字段 + 标注缺失字段）
退出码 3  → 写入「失败」sheet（文件名 + 识别失败原因）
  ↓
输出: invoice_summary_YYYY-MM.xlsx（三个 sheet）
  ↓
(1) 你打开 Excel → 手动填写「需手填」里的空白字段
  ↓
(2) AI 校验：把补完的记录交给 Claude 做一次跨字段合理性检查
```

这个三层结构让批量处理变得健壮：即使有几张发票识别不完整，整个批次不会崩溃，你能清晰地看到哪些需要人工介入。

**这是本章最重要的工程思维：设计降级路径。**

<Callout type="insight" title="AI 校验：别省掉这一步">
手填完「需手填」sheet 之后，还有第二步：让 Claude 做一次**跨字段合理性检查**。这不是可选项——它是降级流的收尾，防止人工填写时引入新的错误。

**重要说明**：Claude Code 本身无法直接读取 `.xlsx` 文件——如果你直接把 Excel 文件扔给它，它会基于猜测给出看似合理的回复，但实际上没有看到任何真实数据。这一步需要分两次交互，才能真正有效。

**第一步：让 Claude 写一个脚本，把「需手填」sheet 的数据打印出来**

打开 Claude Code：

```bash
cd ~/accounting-learner && claude
```

然后说：

```
帮我写一个 Python 脚本，读取
~/accounting-learner/capstone-a/invoice-ocr/outputs/invoice_summary_2026-04.xlsx
里的「需手填」sheet，把每一行的所有字段打印出来，格式清晰易读。
```

Claude 会生成脚本。运行它：

```bash
python3 /tmp/print_sheet.py
```

你会在终端看到类似这样的输出：

```
行 2: 日期=2026-04-03  商家=某某超市  金额=（空）  税号=91110xxxxxxx
行 3: 日期=2026-04-07  商家=（空）    金额=328.00  税号=（空）
...
```

**第二步：把打印出来的文字粘贴给 Claude，做跨字段合理性检查**

把终端输出的文字全部选中、复制，然后对 Claude 说：

```
下面是我在「需手填」sheet 里手填完成后的记录（从终端打印出来的）：

[粘贴刚才的终端输出]

帮我做一次校验：
- 每条记录的日期、商家、税号是不是配得上（同一家商户的税号应一致）
- 金额是不是合理范围（对照同月同类目其它记录）
- 有没有明显的录入失误（比如多/少一位小数）

把可疑的行单独列出来，告诉我可疑在哪里。
```

Claude 会逐行核查，把可疑记录单独列出来并说明原因。你再对照原件确认或修正，然后把「需手填」数据合并进主表。
</Callout>

<Callout type="insight" title="降级流是会计 AI 工作的核心技能">
AI 工具识别率达到 90% 已经是很好的结果了。剩下的 10% 怎么处理，取决于你的设计。

没有降级流的批量处理：遇到一张坏发票就崩溃，或者悄悄丢失数据。

有降级流的批量处理：自动分类处理结果，清晰标注需要人工干预的部分，让你对整个批次的状态一目了然。

这个思维不只适用于 OCR——任何依赖 AI 的工作流都需要它。
</Callout>

## 4. 工具二：bank-classifier · 银行流水分类

### 这个工具做什么？

银行 CSV 流水的每一行是一笔消费，但没有分类。你的任务是把它们自动归入以下类别：

| 类别 | 关键词举例 |
|---|---|
| 餐饮 | 美团、饿了么、麦当劳、肯德基、星巴克 |
| 交通 | 滴滴、高铁、机票、地铁、停车、加油 |
| 办公 | 阿里云、腾讯云、京东企业、文具 |
| 快递 | 顺丰、菜鸟、韵达、极兔 |
| 其它 | 以上都不匹配的 |

分类规则很简单——检查「摘要」字段里有没有这些关键词。这不是机器学习，就是字符串匹配，足够处理大多数真实流水了。

<Callout type="insight" title="「够用」就是最好的设计">
你可能会想：这个分类太简单了，能准吗？

在实际工作中，简单的关键词匹配通常能覆盖 80-90% 的日常消费类别。剩下的 10-20% 归入「其它」，由你定期手动核查。

先把 80% 的自动化做好，比做一个「完美但用不起来的 ML 分类器」更有价值。
</Callout>

<Callout type="tip" title="中国银行流水默认不是 CSV——先把文件转换好">
工商银行、招商银行、建设银行等主流银行的网银导出，默认格式是 **PDF** 或 **XLS/XLSX**，很少直接提供 CSV。在把文件放入 `inputs/` 之前，需要先转换格式。

**最快的路径（适用于大多数银行）**：用 Excel 打开 XLS 文件，点「文件」→「另存为」→ 格式选 **CSV UTF-8（逗号分隔）**，保存即可。

**如果银行只给 PDF**：可以让 Claude 帮你写一个一次性转换脚本：

```
我的银行流水是 PDF，帮我写一个 Python 脚本用 pdfplumber 把它的表格提取出来，
保存成 CSV，列名尽量保留原始名称。
```

**部分银行支持直接导出 CSV**：登录网银后在「下载」或「高级导出」选项里找一找，有的银行（如平安银行企业版）提供 CSV 选项。

格式转换好之后，再继续下面的步骤。
</Callout>

## 5. 工具三：report-aggregator · 多表汇总

### 这个工具做什么？

如果你管理多个部门的费用报表，每个部门每月交一个 Excel，你需要把它们汇总成一张表供月末对账用。

手动复制粘贴很容易出错，也很烦。这个工具自动完成汇总：读取 inputs/ 里所有 `.xlsx` 文件，把它们合并成一张，加上「来源文件」列用于追溯。
