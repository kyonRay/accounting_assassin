# 第 7 章 · 在自己的项目里工作

## 1. 欢迎进入「自己的项目」

前两章我们搭好了工作台（Ch 5）、第一次跟真实的 Claude Code 对话（Ch 6）。`~/accounting-learner/` 这个目录一直都在——现在是时候把它当成一个**真正属于你的项目**，而不只是练习场。

真实项目有三个特征：
- 有一份说明文件，让你（或 AI）下次打开时知道"这里是干嘛的"
- 有组织好的目录结构（脚本在 `scripts/`，输出在 `outputs/`）
- 有版本历史，出了问题能回滚

本章我们来完成第一个特征，同时完成你的**第一个真实会计任务**：用 Python 调用 App 预置的 `aa-ocr` 工具，把发票 PDF 自动提取成结构化数据。

## 2. CLAUDE.md——项目的记忆

### 为什么需要 CLAUDE.md？

每次你打开 Claude Code，它对你的项目是"失忆"的——它不知道你上次在做什么，不知道你的目录结构，不知道你习惯用中文还是英文注释。

`CLAUDE.md` 就是给 Claude 的「项目说明书」。把它放在项目根目录（`~/accounting-learner/CLAUDE.md`），Claude Code 每次启动时会自动读取它，从而了解：
- 这个项目是干什么的
- 目录结构是怎样的
- 你的偏好和约定

<Callout type="tip" title="写 CLAUDE.md 不必完美">
不用把所有东西都写进去——只写你觉得「每次都要向 Claude 解释的事」就够了。
它会随着你的项目慢慢成长，就像工作笔记一样。
</Callout>

## 3. 第一次真实任务：一张发票的 OCR

### aa-ocr 是什么？

记账杀手 App 里预置了一个叫 `aa-ocr` 的命令行工具，它封装了 macOS 系统级的图像识别，能从发票 PDF 或图片里提取：

| 字段 | 说明 |
|---|---|
| `date` | 发票日期（ISO 格式，例如 `2026-04-15`） |
| `vendor` | 销售方公司名称 |
| `amount` | 价税合计金额（含税，单位 CNY） |
| `tax_id` | 销售方纳税人识别号 |

<Callout type="warn" title="aa-ocr 是 App 帮你装好的">
`aa-ocr` 工具是记账杀手 App 在「切换到真实环境」时自动安装的（在 Ch 5 的切换流程里）。

想确认它装好了没有，在终端里输入 `which aa-ocr`：

- 如果显示一条路径（例如 `/usr/local/bin/aa-ocr`），说明装好了。
- 如果什么都没显示，或提示「aa-ocr not found」，说明 App 还没完成安装。

**装失败 / 找不到 aa-ocr 怎么办：** 点右下角的「我卡住了」按钮，App 会自动收集诊断报告（包含 `aa-ocr` 是否找得到、symlink 是否还在等信息），把报告复制下来发给会编程的人——多半几行命令就能修好。**不要**回到 Ch 5「重新走一遍」——Ch 5 → 真实环境的切换是单向的，章节完成标记不会自动重置，重走也只是看一遍流程，不会再次触发安装。

你**不需要**自己写 OCR 代码，也不需要了解它内部实现细节——那些复杂性都被封装进了这个工具。
</Callout>

<Callout type="insight" title="为什么只解析这 4 个字段？">
真实增值税发票上还有发票号、税额（价税分离）、购买方名称 + 税号、税控码等更多字段。本课程把抽取字段缩到最少（日期 / 商家 / 金额 / 税号），只为讲清楚**流程**：读 PDF → 抽字段 → 写 CSV。

真实工作里要补字段非常简单——让 Claude 帮你改 `aa-ocr` 的输出解析就行，流程一样：
- 想要分别记录**不含税金额**和**税额**？跟 Claude 说：「在 CSV 里把 `amount` 拆成 `amount_before_tax` 和 `tax` 两列。」
- 想要**发票号、购买方公司**？跟 Claude 说：「在 Python 脚本里把发票号和购买方公司也加进表格。」

当前 `amount` 字段是**价税合计**（含税总金额），单位是人民币。入账时如果你的科目需要价税分离，按上面方式扩展即可。
</Callout>

`aa-ocr` 的接口非常简单——只接受一个参数：发票文件路径。

```bash
# 处理单张发票，JSON 输出到 stdout
aa-ocr path/to/invoice.pdf
```

典型的成功输出（exit 0，四个字段全部提取出来）：

```json
{
  "source_file": "path/to/invoice.pdf",
  "fields": {
    "date":   { "value": "2026-04-15", "confidence": 0.92 },
    "amount": { "value": 1234.50, "confidence": 0.88, "currency": "CNY" },
    "vendor": { "value": "上海某某商贸有限公司", "confidence": 0.85 },
    "tax_id": { "value": "91310000MA1GH5XF2B", "confidence": 0.90 }
  },
  "raw_text": "...（OCR 出来的原始文字，省略）..."
}
```

如果某个字段没识别出来，它的 `value` 是 `null`，并多一个 `reason` 字段说明原因（例如 `"未识别"`）。

退出码含义（**JSON 总是输出到 stdout，无论退出码是什么**）：

| 退出码 | 含义 |
|---|---|
| `0` | 四个字段（日期、金额、商家、税号）全部提取成功 |
| `1` | 调用方式错误（例如 `aa-ocr` 后面没跟文件路径） |
| `2` | 文件不存在 |
| `3` | 文件存在但完全提取不到文字（图片质量太低、不支持的格式、或扫描件 OCR 失败） |
| `4` | 部分字段提取成功（1-3 个字段有值，其余为 `null`） |

### 准备一张可以跑通的发票

测试 `aa-ocr` 前，先在 `~/accounting-learner/invoices/` 里放一张**真的是发票**的 PDF。按下面顺序找：

1. **优先：你手上现成的发票 PDF**——任何一张电子发票、扫描的纸质发票、`.pdf` / `.png` / `.jpg` 都行，复制到 `~/accounting-learner/invoices/` 里就好。
2. **没有真实发票：让 Claude 帮你生成一张样板发票。** 开终端跑 `cd ~/accounting-learner && claude`，对它说：
   ```
   帮我用 reportlab 在 ~/accounting-learner/invoices/test-invoice.pdf 生成一张
   简单的增值税发票测试 PDF，要包含这些字段（编出来就行，不要用真实信息）：
   - 销售方名称：示例商贸有限公司
   - 纳税人识别号：91310000MA1GH5XF2B
   - 开票日期：2026-04-15
   - 价税合计：1234.50
   ```
   Claude 会自动 `pip install reportlab` 并生成 PDF，然后用这张测试。

<Callout type="warn" title="不要随便抓一个 PDF 来跑">
随便拿一个**不是发票**的 PDF（论文、电子书、广告、扫描收据）去跑 `aa-ocr`，**大概率会拿到退出码 3 或 4**——这不是脚本坏了，是 PDF 里根本没有「开票日期」「纳税人识别号」这些字段可以抽。

看到退出码 3 / 4 / 全 `null` 的字段时，**先检查你喂的是不是真的发票**，再怀疑别的。
</Callout>

<Callout type="warn" title="真实发票放进来之前，先想一下隐私">
真实发票数据 = 真实客户姓名 + 真实税号 + 真实金额。**当你后面用 `claude` 或 `claude --continue` 让 Claude 帮你调试这个脚本时，Claude 会读发票文件的内容——文件内容会发到 Anthropic 服务器。**

**判断标准：**
- ✅ 这台电脑 + 这个工作目录，是你练习 / 学习用的、不涉及公司客户？真实文件可以放。
- ⚠️ 这是公司发的工作机，发票来自真实客户？**先把姓名 / 税号 / 金额脱敏再放**——可以让 Claude 帮你写一个脱敏脚本（把姓名换成「客户 A」、税号换成 `91310000XXXXXXXX1`、金额抹零）。

Ch 6 末尾的 _「财务数据隐私底线」_ 列了完整清单（客户身份、银行卡号、工资条等），不记得了**可以翻回去看一眼**。
</Callout>

随着练习增多，你会越来越擅长描述需求，Claude 写的代码质量也会越来越高。
</Callout>

## 4. `--continue` 跨会话延续

### 为什么需要 --continue？

Claude Code 默认每次启动都是全新会话——之前的对话内容不会保留。但在真实工作中，你经常需要「继续昨天做到一半的事」。

`claude --continue` 会恢复上一次的会话上下文，让 AI 记得：
- 你们上次在讨论什么
- 写了哪些文件
- 有哪些决定还没做完

加上你刚写的 `CLAUDE.md`，Claude 会同时拥有：
- 项目的静态背景（CLAUDE.md）
- 上次对话的动态上下文（--continue）

<Callout type="insight" title="--continue 节省的是「讲背景」的时间">
没有 --continue，每次开新对话你都要解释：「我有一个 invoice_ocr.py 脚本，上次你帮我写的，现在我想扩展它……」
有了 --continue，直接说「把刚才的脚本扩展一下」就够了。
</Callout>

### 动手：体验跨会话延续

<RealStep
  id="continue-flow-tried"
  command="cd ~/accounting-learner && claude --continue"
>
  关闭当前终端窗口，重新打开一个新的终端窗口。然后运行上面的命令。

  Claude 会显示上次会话的摘要，然后等待你的下一步指令。

  试着对它说（先不用真的做，感受一下它的回应）：

  ```
  把刚才写的 invoice_ocr.py 扩展一下：
  接受一个目录路径，批量处理目录里所有的 PDF 文件，
  把结果汇总输出到 outputs/ocr_results.csv
  ```

  观察 Claude 如何基于上次的对话来回应（它会引用之前写的脚本结构）。

  看到 Claude 的回应后，输入 `/exit` 退出，然后点「我跑完了」。

  （这个扩展功能我们在 Ch 14 的毕业作品里会真正实现——现在只是提前感受一下工作流。）
</RealStep>
