# 合并单元格 Bug 演示说明

## 场景描述

在 Excel / WPS 里，财务报表经常有这样的格式：

```
| 类目       | 金额   |
|------------|--------|
| 办公用品   | 120.00 |
|            | 88.00  |   ← 这行的"类目"单元格与上面合并
| 交通费     | 380.50 |
| 餐饮招待   | 256.00 |
|            |        |   ← 小计行（合并单元格）
| 合计       |        |   ← 合计行
```

## 为什么用 pandas 读取时会出问题

`pandas.read_excel()` 遇到合并单元格时，只在第一行填入值，后续合并的行填 `NaN`（空值）。

如果你的汇总脚本用 `df.groupby('类目').sum()`，那些类目是 `NaN` 的行就会被忽略，
导致**脚本输出的合计数字比真实数字小**。

这就是"静默 bug"：脚本跑通了、没有报错，但输出结果是错的。

## 练习目标

学会"对数"验证方法：

1. 先用脚本跑出汇总数字
2. 再手动算一遍总金额（打开 Excel 用计算器加）
3. 两个数字比较——不一致就说明脚本有问题

不要假设脚本输出是对的，要用独立的方式验证。

## 如何在本地复现

1. 用 WPS 或 Excel 创建一个有合并单元格的简单表格（两行合并一个类目单元格）
2. 保存为 `merged_demo.xlsx`
3. 用下面的 Python 脚本读取：

```python
import pandas as pd
df = pd.read_excel('merged_demo.xlsx')
print(df)
print('合计：', df['金额'].sum())
```

4. 观察输出：合并单元格对应的行，类目列是 NaN，对应金额没有被正确归类到任何分组

## 真实工作中的处理方案

让 Claude Code 帮你处理合并单元格：

```
我有一个 Excel 文件，里面有合并单元格。
pandas 读取后合并单元格的行变成了 NaN。
请帮我写代码把 NaN 用上一行的值填充（forward fill）后再汇总。
```
