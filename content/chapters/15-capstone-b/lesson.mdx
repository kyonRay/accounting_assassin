## 1. 你为什么要把三个工具串起来

Ch 14 你建了三个独立运行的 Python 工具：

| 工具 | 目录 | 干什么 |
|---|---|---|
| **invoice-ocr** | `capstone-a/invoice-ocr/` | 批量发票 OCR → Excel 汇总 |
| **bank-classifier** | `capstone-a/bank-classifier/` | 银行流水 CSV → 分类 CSV |
| **report-aggregator** | `capstone-a/report-aggregator/` | 多 Excel → 统一汇总表 |

每个工具单独能跑，但每次月末你还是要手动一个一个运行它们——顺序容易搞错，遗漏一步就要重来。

**这就是 Ch 15 要解决的问题**：用 Claude Code 的 **Skill** 把四个步骤编排成一个工作流，说一句「帮我做本月结账」，Claude 自动按顺序完成全部工作。

这不是写代码——这是把你已有的工具**组合成一个 AI 同事可以执行的标准操作程序**。

<Callout type="insight" title="从「三个工具」到「一个工作流」：本质是什么？">
Ch 14 你做的是「搭工具」——每个工具关注自己的事，不依赖彼此。这是正确的工程原则：先把每个部件跑通。

Ch 15 你做的是「串流程」——把已有工具组合起来，加一个缺失的环节（凭证生成），形成端到端的月末结账流水线。

区别：工具是锤子和锯子，工作流是「知道什么时候用锤子、什么时候用锯子、按什么顺序做」的施工方案。
</Callout>

## 3. 第四步：凭证生成（新工具）

Ch 14 的三个工具覆盖了「发票 OCR → 流水分类 → 报表汇总」，但月末结账还差一个环节：**凭证生成**。

会计凭证（也叫记账凭证）是每笔业务的书面记录，格式是：

| 凭证号 | 日期 | 摘要 | 借方科目 | 贷方科目 | 金额 |
|---|---|---|---|---|---|
| 2026-05-001 | 2026-05-03 | 顺丰快递 | 管理费用-快递 | 银行存款 | 28.00 |
| 2026-05-002 | 2026-05-07 | 美团外卖 | 管理费用-餐饮 | 银行存款 | 136.50 |

**做法**：把 bank-classifier 的分类结果（已知借方科目）和 invoice-ocr 的 Excel 汇总（已知日期/商家/金额）按「日期+金额」对应配对，输出标准格式的凭证 CSV。

不匹配的行（有银行记录但找不到对应发票，或反之）单独列一个「待核查」sheet，等你手动处理。

### 动手：让 Claude 搭建 voucher-gen 项目

<RealStep
  id="voucher-script-scaffolded"
  command="cd ~/accounting-learner && claude"
>
  打开终端，进入工作目录启动 Claude Code，然后对它说：

  ```
  在 ~/accounting-learner/capstone-b/voucher-gen/ 下帮我创建凭证生成工具：

  目录结构：
  - scripts/make_vouchers.py   主脚本
  - outputs/                   凭证 CSV 输出目录（已存在，不用创建）
  - README.md                  项目说明

  make_vouchers.py 要求：
  1. 读取 ~/accounting-learner/capstone-a/invoice-ocr/outputs/ 下最新的 invoice_summary_YYYY-MM.xlsx
     取「主表」sheet 里的发票记录（列：日期/商家/金额/税号/文件名）
  2. 读取 ~/accounting-learner/capstone-a/bank-classifier/outputs/ 下最新的 bank_classified_YYYY-MM.csv
     取全部分类记录（列：日期/摘要/金额/分类 等）
  3. 按「日期相差<=1天 AND 金额相差<=0.01」做模糊匹配，配对发票与银行流水
  4. 对每对匹配记录，生成一行凭证：
     - 凭证号（YYYY-MM-序号，如 2026-05-001）
     - 日期（取发票日期）
     - 摘要（银行摘要字段）
     - 方向判断（根据银行流水金额正负或收/支标记）：
       * 出账（支出，金额 < 0 或收支标记为「支」）：
         借方科目 ∈ [管理费用-餐饮 / 管理费用-差旅 / 管理费用-交通 /
                     管理费用-办公用品 / 管理费用-快递 / 管理费用-招待 /
                     管理费用-租赁 / 管理费用-水电 / 管理费用-福利 /
                     税金及附加 / 财务费用 / 管理费用-其他]
         贷方科目 = 银行存款
       * 入账（收入，金额 > 0 或收支标记为「收」）：
         借方科目 = 银行存款
         贷方科目 ∈ [主营业务收入 / 应收账款 / 营业外收入 / 财务费用-利息收入]
     - 金额（取绝对值）
  5. 未匹配的银行记录和未匹配的发票记录，分别写入「待核查-银行」和「待核查-发票」sheet
  6. 输出到 outputs/vouchers_YYYY-MM.xlsx（三个 sheet：凭证/待核查-银行/待核查-发票）
  7. 运行结束打印：生成凭证 X 张，待核查-银行 Y 笔，待核查-发票 Z 张

  只用 pandas、openpyxl、pathlib、datetime、sys。
  如果输入文件不存在，打印提示后正常退出（不崩溃）。
  ```

  Claude 会帮你创建脚本。确认文件创建完成后，输入 `/exit` 退出，然后点「我跑完了」。

  <Callout type="tip" title="暂时没有 Ch 14 的输出文件？">
  如果 capstone-a 的 inputs/ 是空的（你还没有真实发票/流水），`make_vouchers.py` 在找不到文件时应该打印提示后退出——这也是正确的输出。

  或者让 Claude 给脚本加一个 `--demo` 参数，用假数据走一遍完整流程（生成凭证 + 两个「待核查」sheet），验证逻辑正确。
  </Callout>

  <Callout type="insight" title="为什么借贷方向要根据收支判断，而不是固定写银行存款？">
  凭证的核心规则是**借贷平衡、方向正确**。银行存款是一个资产类科目：

  - **出账**（付款）：银行存款减少 → 贷方写银行存款；费用科目增加 → 借方写费用科目
  - **入账**（收款）：银行存款增加 → **借方写银行存款**；收入/应收款减少 → 贷方写收入科目

  如果把贷方固定写「银行存款」，收款凭证就会变成「借主营业务收入 / 贷银行存款」——借贷方向完全反了，任何审计软件都会报错。

  脚本里的分类映射只是**起步集合**，实际业务中：
  - 美团外卖可能是招待费（接待客户）、福利费（员工加班餐）或管理费用（日常订餐），要根据摘要和审批单来判断
  - 真实企业的科目表通常有 20+ 个末级费用科目

  脚本让 Claude 做初步分类，你负责最终审核——这是 AI 辅助记账的正确分工。
  </Callout>
</RealStep>

## 4. 写 Skill：month-end-close 编排说明书

四个工具现在都有了（三个来自 Ch 14，凭证生成是刚搭好的）。现在写 Skill——这是整个工作流的「目录和指挥官」。

**为什么用 Skill 而不是直接写一个 Python 脚本来串联？**

Python 脚本可以把四个脚本串成一个 `run_all.py`，但它是静态的：步骤顺序写死了，每一步遇到问题要报错、停下来。Skill 是给 Claude 的说明书——Claude 执行 Skill 时是动态的：它能理解上下文、在一步失败时主动询问你怎么办、根据当月数据情况灵活调整。

**说明书的格式**（和 Ch 9 的 organize-invoices 完全一样）：

```
~/.claude/skills/
└── month-end-close/
    └── SKILL.md
```

<RealStep
  id="skill-orchestrator-written"
  command="mkdir -p ~/.claude/skills/month-end-close && claude"
>
  先创建目录，然后让 Claude 帮你把下面的内容写入 `~/.claude/skills/month-end-close/SKILL.md`：

  ```
  帮我创建 ~/.claude/skills/month-end-close/SKILL.md，内容如下：

  ---
  name: month-end-close
  description: 月末结账：发票批量 OCR、银行流水分类、凭证生成、月报汇总，产出 month_end_<YYYY-MM>.xlsx。每月初做月报前用。
  ---

  # month-end-close

  ## 何时使用

  当用户说「帮我做本月结账」「做月末结账」「整理本月财务」「月报汇总」时，
  使用这个 skill。

  ## 四步工作流

  ### 第一步：发票批量 OCR（invoice-ocr）

  运行 ~/accounting-learner/capstone-a/invoice-ocr/scripts/batch_ocr.py
  输入：~/accounting-learner/capstone-a/invoice-ocr/inputs/
  输出：~/accounting-learner/capstone-a/invoice-ocr/outputs/invoice_summary_YYYY-MM.xlsx

  如果「需手填」sheet 非空，停下来告诉用户需要手动补全缺失字段，等用户确认后再继续。

  ### 第二步：银行流水分类（bank-classifier）

  运行 ~/accounting-learner/capstone-a/bank-classifier/scripts/bank_classify.py
  输入：~/accounting-learner/capstone-a/bank-classifier/inputs/ 下第一个 CSV
  输出：~/accounting-learner/capstone-a/bank-classifier/outputs/bank_classified_YYYY-MM.csv

  ### 第三步：凭证生成（voucher-gen）

  运行 ~/accounting-learner/capstone-b/voucher-gen/scripts/make_vouchers.py
  输入：第一步和第二步的输出文件
  输出：~/accounting-learner/capstone-b/voucher-gen/outputs/vouchers_YYYY-MM.xlsx

  如果「待核查」sheet 非空，告知用户有多少行待核查，让用户决定是否继续。

  ### 第四步：月报汇总（report-aggregator）

  运行 ~/accounting-learner/capstone-a/report-aggregator/scripts/aggregate.py
  把 invoice_summary_YYYY-MM.xlsx 和 vouchers_YYYY-MM.xlsx 都放入
  ~/accounting-learner/capstone-a/report-aggregator/inputs/ 后运行汇总
  输出：~/accounting-learner/capstone-a/report-aggregator/outputs/aggregated_YYYY-MM.xlsx

  最后把 aggregated_YYYY-MM.xlsx 重命名为 month_end_YYYY-MM.xlsx 并移到
  ~/accounting-learner/outputs/ 下。

  ## 注意

  - YYYY-MM 统一用当月日期
  - 每步运行前先确认输入文件存在，不存在就提示用户
  - 遇到任何退出码非 0 的错误，把错误信息展示给用户，等待用户指令后再决定是否继续
  - 不要修改 inputs/ 下的原始文件
  ```

  确认 `SKILL.md` 写入完成后，输入 `/exit` 退出，然后点「我跑完了」。

  </Callout>

## 5. 安装 Hook：capstone-b 文件变化自动写日志

这一步是可选的加分项，但很值得做——它让你知道「这个月 Claude 在 capstone-b 里动了哪些文件」，万一出问题有日志可查。

**原理**（和 Ch 10 完全一样）：

- `PostToolUse` + `matcher: "Edit"` — 每次 Claude 用 Edit 工具修改文件后触发
- 命令只做一件事：把时间戳和文件名追加写入日志文件（只追加，不删除，永远安全）

<RealStep
  id="hook-capstone-b-installed"
  command=""
>
  打开（或创建）`~/accounting-learner/.claude/settings.local.json`，把下面这段 JSON 合并进去：

  ```json
  {
    "hooks": {
      "PostToolUse": [
        {
          "matcher": "Edit",
          "hooks": [
            {
              "type": "command",
              "command": "echo \"[$(date '+%Y-%m-%d %H:%M:%S')] Edit: $(jq -r '.tool_input.file_path // empty')\" >> ~/accounting-learner/.month-end.log"
            }
          ]
        }
      ]
    }
  }
  ```

  <Callout type="tip" title="为什么用 jq 而不是环境变量？">
  Claude Code 的 Hook 通过**标准输入（stdin）**传入一个 JSON 对象，包含触发事件的详细信息。
  要提取其中的字段（比如被编辑文件的路径 `tool_input.file_path`），需要用 `jq` 解析 stdin。

  `$CLAUDE_TOOL_INPUT_PATH` 这样的环境变量并不存在——Hook 的输入通道是 stdin，不是环境变量。

  如果还没有安装 `jq`：
  ```bash
  brew install jq
  ```
  （Ch 5 已装好 Homebrew，直接运行即可）
  </Callout>

  <Callout type="warn" title="如果文件已存在，只合并 hooks 部分">
  如果 `settings.local.json` 已经有其他配置（Ch 10 写过），**不要直接覆盖整个文件**。只把 `"hooks": { ... }` 这一段合并进已有的 JSON 对象里。遇到不确定的情况，把文件内容复制给 Claude，说「帮我把这段 hooks 配置合并进去」。
  </Callout>

  配置完成后，打开一个新的 Claude Code 会话，让它随便编辑一个 capstone-b 里的文件，然后检查日志是否出现了记录：

  ```bash
  cat ~/accounting-learner/.month-end.log
  ```

  看到时间戳记录之后，点「我跑完了」。
</RealStep>

     ```bash
     cat ~/.claude/skills/month-end-close/SKILL.md
     ```
  3. **description 措辞**：如果说「做月末结账」没触发，换一句更接近 description 字段措辞的说法，比如「月末结账发票银行汇总」。

  常见情况：
  - **输入文件不存在**：放入测试文件后让 Claude 重试那一步
  - **Python 报错**：把报错信息粘给 Claude，它会帮你修复脚本后重试
  - **OCR 退出码 4**：有发票字段识别不完整——打开「需手填」sheet，补全后告诉 Claude 继续

  出错不代表工作流设计有问题——正是因为工作流知道怎么处理错误，才叫「工程化」。
  </Callout>

  看到最终输出文件或 Claude 成功报告全部步骤完成之后，点「我跑完了」。

  **季末税务申报、年末对账、客户账单生成……都可以是一句话触发的工作流。**

  ### 给自己一个交代

  你用这门课证明了：**AI 编程工具不是程序员的专属技能**。只要你能清晰地描述一件工作「需要做什么、按什么顺序、注意什么」，你就能把它变成一个 Claude 能执行的 Skill。

  这门课的知识会过时——工具版本会更新，界面会变，命令可能有出入。但「清晰地描述你想要什么，然后让 AI 来实现」这个工作方式，会一直有效。

  <Callout type="insight" title="这不是终点，是起点">
  你现在有了一套工具箱：Claude Code、Codex、Cursor、Skill、Hook、MCP。

  比工具更重要的，是你在这门课里练习的**思维方式**：
  - 遇到重复工作，想「能自动化吗？」
  - 遇到 AI 犯错，不慌张，用 `git restore .` 撤销，描述清楚问题再试一次
  - 遇到新工具，先问「它解决什么问题？和我已有的工具比，什么时候用它？」

  带着这套工具箱和思维方式走出这门课，去解决你工作里真实的问题。
  </Callout>
