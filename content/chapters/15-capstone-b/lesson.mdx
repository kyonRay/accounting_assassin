## 1. 你为什么要把三个工具串起来

Ch 14 你建了三个独立运行的 Python 工具：

| 工具 | 目录 | 干什么 |
|---|---|---|
| **invoice-ocr** | `capstone-a/invoice-ocr/` | 批量发票 OCR → Excel 汇总 |

| **report-aggregator** | `capstone-a/report-aggregator/` | 多 Excel → 统一汇总表 |

每个工具单独能跑，但每次月末你还是要手动一个一个运行它们——顺序容易搞错，遗漏一步就要重来。

**这就是 Ch 15 要解决的问题**：用 Claude Code 的 **Skill** 把四个步骤编排成一个工作流，说一句「帮我做本月结账」，Claude 自动按顺序完成全部工作。

这不是写代码——这是把你已有的工具**组合成一个 AI 同事可以执行的标准操作程序**。

<Callout type="insight" title="从「三个工具」到「一个工作流」：本质是什么？">
Ch 14 你做的是「搭工具」——每个工具关注自己的事，不依赖彼此。这是正确的工程原则：先把每个部件跑通。

Ch 15 你做的是「串流程」——把已有工具组合起来，加一个缺失的环节（凭证生成），形成端到端的月末结账流水线。

区别：工具是锤子和锯子，工作流是「知道什么时候用锤子、什么时候用锯子、按什么顺序做」的施工方案。
</Callout>

## 3. 第四步：凭证生成（新工具）

Ch 14 的三个工具覆盖了「发票 OCR → 流水分类 → 报表汇总」，但月末结账还差一个环节：**凭证生成**。

会计凭证（也叫记账凭证）是每笔业务的书面记录，格式是：

| 凭证号 | 日期 | 摘要 | 借方科目 | 贷方科目 | 金额 |
|---|---|---|---|---|---|
| 2026-05-001 | 2026-05-03 | 顺丰快递 | 管理费用-快递 | 银行存款 | 28.00 |
| 2026-05-002 | 2026-05-07 | 美团外卖 | 管理费用-餐饮 | 银行存款 | 136.50 |

**做法**：把 bank-classifier 的分类结果（业务分类标签）和 invoice-ocr 的 Excel 汇总（已知日期/商家/金额）按「日期+金额」对应配对，再用**科目映射表**把业务标签翻译成借方科目，输出标准格式的凭证 CSV。

匹配不上的行（有银行记录但找不到对应发票，或反之，或科目映射表里没有这个标签）单独列到 `unmatched.csv` 和「待核查」sheet，等你手动处理。

### 关键概念：分类标签 ≠ 借方科目

bank-classifier 输出的「分类」列（如 `餐饮`、`办公`、`差旅`）是**业务分类标签**——它告诉你这笔钱花在什么类型的业务上。但凭证里的「借方科目」是会计科目表里的标准名称（如 `管理费用-业务招待费`），格式固定、和企业的科目表一一对应。

**这两者不是一回事**——同一个业务标签在不同企业可能对应不同的末级科目，且新员工餐和招待客户餐的科目也不同。所以中间需要一张「分类标签 → 借方科目」的映射表：

```python
# subject_map.py（建议放在 capstone-b/voucher-gen/scripts/ 下，单独一个文件方便修改）
# 注意：这张表是「会计自己改的」，不是 AI 决定的。
# AI 用这张表去映射；遇到表里没有的标签 → 进 unmatched.csv，等会计判断。
subject_map = {
    "餐饮":   "管理费用-业务招待费",
    "办公":   "管理费用-办公费",
    "差旅":   "管理费用-差旅费",
    "交通":   "管理费用-交通费",
    "通讯":   "管理费用-通讯费",
    "云服务": "管理费用-IT服务费",
    "快递":   "管理费用-邮电费",
    "租赁":   "管理费用-租赁费",
    "水电":   "管理费用-水电费",
    "福利":   "应付职工薪酬-福利费",
    "工资":   "应付职工薪酬-工资",
    "税金":   "税金及附加",
    "利息":   "财务费用-利息支出",
    "手续费": "财务费用-手续费",
    "收入":   "主营业务收入",     # 入账方向用
    "退款":   "其他应付款",
}
```

<Callout type="warn" title="为什么不让 AI 自动选择借方科目？">
科目选择影响审计、税务、报表科目余额——错一个，月报里整张表就要重做。会计科目表是企业财务制度的一部分，必须由会计本人维护、明文写死，不能让 AI 推测。

AI 的职责到「按映射表翻译」为止；遇到表里没有的标签，AI **不**默认填「管理费用-其他」，而是**全部进 `unmatched.csv`**，会计逐一判断后再决定加哪条新映射。
</Callout>

  <Callout type="insight" title="为什么借贷方向要根据收支判断，而不是固定写银行存款？">

  - **出账**（付款）：银行存款减少 → 贷方写银行存款；费用科目增加 → 借方写费用科目
  - **入账**（收款）：银行存款增加 → **借方写银行存款**；收入/应收款减少 → 贷方写收入科目

  如果把贷方固定写「银行存款」，收款凭证就会变成「借主营业务收入 / 贷银行存款」——借贷方向完全反了，任何审计软件都会报错。

  所以脚本里 `DEBIT_MAP` 和 `CREDIT_MAP` 是两张表 —— 出账查前者，入账查后者。

  脚本里的映射表只是**起步集合**，实际业务中：
  - 美团外卖可能是招待费（接待客户）、福利费（员工加班餐）或管理费用（日常订餐），要根据摘要和审批单来判断

  </Callout>

  <Callout type="warn" title="为什么匹配规则要保守（同日 + 同金额），而不是「相差 1 天也算」？">
  真实银行数据里有几类容易让宽匹配规则误配的情况：

  - **信用卡入账日错位**：商户结算和银行入账时间差 1-3 天很常见，且不固定
  - **同日重复金额**：一天里多次刷同样金额（如多次打车），没有发票锚点根本无法区分
  - **工资/税金/利息**：根本没有对应发票，宽匹配会把它们错配到任意金额接近的发票上

  保守规则的代价：手动配对的笔数会多一些 —— 但**错配比漏配难得多发现**，错配会污染整个月的凭证账。

  会计宁可花 5 分钟手动配 20 笔进了「待核查-银行」的记录，也不要让 AI 把 20 笔错配上交报表。

## 4. 写 Skill：month-end-close 编排说明书

四个工具现在都有了（三个来自 Ch 14，凭证生成是刚搭好的）。现在写 Skill——这是整个工作流的「目录和指挥官」。

**为什么用 Skill 而不是直接写一个 Python 脚本来串联？**

Python 脚本可以把四个脚本串成一个 `run_all.py`，但它是静态的：步骤顺序写死了，每一步遇到问题要报错、停下来。Skill 是给 Claude 的说明书——Claude 执行 Skill 时是动态的：它能理解上下文、在一步失败时主动询问你怎么办、根据当月数据情况灵活调整。

**说明书的格式**（和 Ch 9 的 organize-invoices 完全一样）：

```
~/.claude/skills/
└── month-end-close/
    └── SKILL.md
```

<RealStep
  id="skill-orchestrator-written"
  command="mkdir -p ~/.claude/skills/month-end-close && claude"
>
  先创建目录，然后让 Claude 帮你把下面的内容写入 `~/.claude/skills/month-end-close/SKILL.md`：

  ````
  帮我创建 ~/.claude/skills/month-end-close/SKILL.md，内容如下：

  ---
  name: month-end-close
  description: 月末结账：发票批量 OCR、银行流水分类、凭证生成、月报汇总，产出 month_end_<YYYY-MM>.xlsx。每月初做月报前用。
  ---

  # month-end-close

  ## 何时使用

  当用户说「帮我做本月结账」「做月末结账」「整理本月财务」「月报汇总」时，
  使用这个 skill。

  ## 步骤 0：先确认账期 `<period>`

  在跑任何脚本之前，先问用户：

  ```
  你要关哪一个月的账？(例如 2026-04) [默认: 2026-04]
  ```

  - **账期 = 上一个完整月份**。今天是 2026-06-02，默认就是 2026-05；
    今天是 2026-01-05，默认就是 2025-12。**不是当月**，月末关的是上月的账。
  - 用户按回车 = 接受默认（上月）；也可以输入别的月份补做。
  - 拿到 `<period>` 之后，下面四步**全部用同一个 `<period>` 串起来**，
    并把 `--period <period>` 传给每个脚本。文件名、子目录名、汇总名一律用这个，
    绝对不能在任何步骤里用 `datetime.now()` 拼文件名。

  ## 四步工作流

  ### 第一步：发票批量 OCR（invoice-ocr）

  运行 `~/accounting-learner/capstone-a/invoice-ocr/scripts/batch_ocr.py --period <period>`

  输入：`~/accounting-learner/capstone-a/invoice-ocr/inputs/<period>/`（按账期分子目录）
  输出：`~/accounting-learner/capstone-a/invoice-ocr/outputs/invoice_summary_<period>.xlsx`

  如果「需手填」sheet 非空，停下来告诉用户需要手动补全缺失字段，等用户确认后再继续。

  ### 第二步：银行流水分类（bank-classifier）

  运行 `~/accounting-learner/capstone-a/bank-classifier/scripts/bank_classify.py --period <period>`

  输入：`~/accounting-learner/capstone-a/bank-classifier/inputs/<period>/` 下的 CSV
  （和 aggregator 同样的约定 —— 按账期分子目录）。

  **不要『取第一个 CSV』**：如果 `inputs/<period>/` 里有多个 CSV
  （测试文件、上月遗留、不同卡的导出），按文件名匹配规则
  （比如 `bank_<period>*.csv`）筛选；不匹配的文件**报错并列出**，
  让用户决定该删还是该改名。Claude 默默拿错账期是月结里最难发现的错。

  输出：`~/accounting-learner/capstone-a/bank-classifier/outputs/bank_classified_<period>.csv`

  ### 第三步：凭证生成（voucher-gen）

  运行 `~/accounting-learner/capstone-b/voucher-gen/scripts/make_vouchers.py --period <period>`
  输入：第一步和第二步同 `<period>` 的输出文件（`invoice_summary_<period>.xlsx`、
  `bank_classified_<period>.csv`）—— 显式按 `<period>` 找文件，不要『拿 outputs/ 下最新的』。
  输出：
    - `~/accounting-learner/capstone-b/voucher-gen/outputs/vouchers_<period>.xlsx`
    - `~/accounting-learner/capstone-b/voucher-gen/outputs/unmatched_<period>.csv`

  如果「待核查」sheet 非空 或 `unmatched_<period>.csv` 非空，
  把行数报给用户，等用户处理完（补 subject_map、手动配对）再决定是否继续第四步。
  绝对不要默认填「管理费用-其他」把 unmatched 行混入主表。

  ### 第四步：月报汇总（report-aggregator）

  **步骤 0（必须先做）：组织 `inputs/<period>/` 子目录**

  问题：`inputs/` 里很可能既有上月遗留的文件，也有本月新放进去的文件。
  Claude 不知道哪些是本月该汇总的，会把两个月的数据都混进 `month_end_YYYY-MM.xlsx`，
  那么 5 月报表里就会出现 4 月数据 —— 这是月结里最难发现也最致命的错。

  两种处理方式，**任选其一**：

  - **(a) 每次跑前清空 inputs/**：
    `rm -f ~/accounting-learner/capstone-a/report-aggregator/inputs/*.xlsx`
    —— 简单，但你失去了上月文件的归档。

  - **(b) 按账期分子目录（推荐）**：
    把汇总输入按账期分别放进
    `~/accounting-learner/capstone-a/report-aggregator/inputs/2026-05/` /
    `~/accounting-learner/capstone-a/report-aggregator/inputs/2026-04/` …
    aggregator 跑 5 月时**只读** `inputs/2026-05/` 这个子目录，不碰其它月份。
    `aggregate.py --period 2026-05` 自动只读对应子目录。

  **步骤 1：复制本月输入到 `inputs/<period>/` 并运行汇总**

  - 把 `invoice_summary_<period>.xlsx` 和 `vouchers_<period>.xlsx` 复制到
    `~/accounting-learner/capstone-a/report-aggregator/inputs/<period>/` 下
    （不要直接放在 `inputs/` 根目录）
  - 运行 `~/accounting-learner/capstone-a/report-aggregator/scripts/aggregate.py --period <period>`
  - 输出：`~/accounting-learner/capstone-a/report-aggregator/outputs/aggregated_<period>.xlsx`

  最后把 `aggregated_<period>.xlsx` 重命名为 `month_end_<period>.xlsx` 并移到
  `~/accounting-learner/outputs/` 下。

  ### 闭环校验（最后一步：防「假成功」）

  脚本结束前必须打印闭环校验摘要：

  ```
  ===== 月结闭环校验 =====
  会计期间: <period>
  凭证总笔数 (vouchers_<period>.xlsx · 凭证 sheet)  = N
  银行流水总笔数 (bank_classified_<period>.csv)     = M
  待核查笔数 (unmatched_<period>.csv)               = U
  校验:  N + U  应该 =  M  （差 ≤ 1 笔人工兜底）
  ```

  如果 `N + U ≠ M`，最后一句话**必须**红字提示：

  ```
  ⚠️  数字不闭环，<period> 账需要会计逐笔核对再封账
  ```

  **判断成功的判据：** 不是『SKILL 跑完了』，而是『最后那行打印的 `N + U = M`』。
  跑完不等于跑对——闭环数字对得上，才能封账。

  ## 注意

  - **账期是什么？** 月末结账 = 关**上一个完整月份**的账。
    比如今天是 2026-06-02，默认账期就是 2026-05；今天若是 2026-01-05，默认账期就是 2025-12。
  - **脚本启动时先问一次：『关哪个月的账？』**，默认上月，
    同时接受 `--period YYYY-MM` 命令行参数以便非交互运行。
  - **YYYY-MM 一律取自用户输入的会计期间，不要用 `datetime.now()` 拼文件名**——
    会计要的是「关账月份」，不是「跑脚本的今天」。
  - **aggregator 不要『拿第一个 CSV/xlsx』**：`inputs/<period>/` 里如果有多个 xlsx
    （invoice_summary / vouchers / 历史归档），Claude 默认会随机选一个。
    改成：**enumerate 所有 `inputs/<period>/*.xlsx`，按文件名匹配规则识别
    （`invoice_summary_<period>.xlsx` / `vouchers_<period>.xlsx`），
    不匹配的文件报错并列出**，不要静默忽略。
  - 每步运行前先确认输入文件存在，不存在就提示用户
  - 遇到任何退出码非 0 的错误，把错误信息展示给用户，等待用户指令后再决定是否继续
  - 不要修改 inputs/ 下的原始文件
  ````

  确认 `SKILL.md` 写入完成后，输入 `/exit` 退出，然后点「我跑完了」。

  <Callout type="tip" title="description 是触发的关键（和 Ch 9 一样）">
  Skill 靠 `description` 字段做语义匹配——Claude 读到「帮我做本月结账」这句话时，会在 `~/.claude/skills/` 下找和这个描述最接近的 SKILL.md，然后按里面的步骤来做。

  写得越像你平时说话的方式，识别越准。
  </Callout>

  <Callout type="tip" title="为什么用绝对路径？">
  Claude 启动会话的目录每次可能不同——从桌面启动和从项目目录启动，当前目录就不一样。Skill 里写绝对路径（`~/accounting-learner/...`），无论从哪里启动都能找到文件；写相对路径则在会话目录不对时直接报「文件不存在」。
  </Callout>
</RealStep>

## 5. 安装 Hook：accounting-learner 文件变化自动写日志

这一步是可选的加分项，但很值得做——它让你知道「这个月 Claude 在 `~/accounting-learner/` 里动了哪些文件」，万一出问题有日志可查。

**原理**（和 Ch 10 完全一样）：

- `PostToolUse` + `matcher: "Edit|Write|MultiEdit"` — Claude 用任意一种「写文件」工具之后触发
- 命令只做一件事：如果被改的文件在 `~/accounting-learner/` 下，就把时间戳、工具名、文件路径追加写入日志文件（只追加，不删除，永远安全）

<Callout type="warn" title="为什么 matcher 要写三种工具，不只是 Edit？">
- `Edit` 只匹配「修改已存在的文件」
- `Write` 用于「写新文件」（voucher-gen 项目里 Claude 创建 `make_vouchers.py` 走的就是 Write，不是 Edit）
- `MultiEdit` 是「一次会话里改多个文件」

只写 `"Edit"` 的话，本章 voucher-gen 项目的脚手架步骤一条日志都不会留下 —— 那就失去了「Claude 这次月结改了哪些文件」的全部价值。
</Callout>

### 第 0 步：装 jq（这个 hook 用 jq 读 stdin）

<Callout type="warn" title="先确认 jq 已安装，否则 hook 会静默失败">
Claude Code 的 Hook 通过**标准输入（stdin）**传入一个 JSON 对象，要提取其中的 `tool_input.file_path` 字段需要用 `jq`。

打开终端跑：

```bash
command -v jq >/dev/null 2>&1 || brew install jq
```

如果终端里啥都不打印 → 你已经装过了。如果开始安装 → 等装完。**不装 jq 这个 hook 会写出空文件名 `<jq-missing>`，但 hook 本身不报错** —— 这种「悄悄出错」的状态最难调。
</Callout>

<RealStep
  id="hook-capstone-b-installed"
  command=""
>
  打开（或创建）`~/accounting-learner/.claude/settings.local.json`，把下面这段 JSON 合并进去：

  ```json
  {
    "hooks": {
      "PostToolUse": [
        {
          "matcher": "Edit|Write|MultiEdit",
          "hooks": [
            {
              "type": "command",
              "command": "INPUT=$(cat); TOOL=$(echo \"$INPUT\" | jq -r '.tool_name // \"<unknown>\"' 2>/dev/null || echo '<jq-missing>'); FILE=$(echo \"$INPUT\" | jq -r '.tool_input.file_path // \"<empty>\"' 2>/dev/null || echo '<jq-missing>'); case \"$FILE\" in \"$HOME/accounting-learner/\"*) echo \"[$(date '+%Y-%m-%d %H:%M:%S')] $TOOL: $FILE\" >> \"$HOME/accounting-learner/.month-end.log\" ;; esac"
            }
          ]
        }
      ]
    }
  }
  ```

  <Callout type="insight" title="这条 command 在做什么 —— 逐段解释">
  1. `INPUT=$(cat)` — 把 stdin 读进变量（Hook 的输入通道是 stdin，不是环境变量）
  2. `TOOL=$(echo "$INPUT" | jq -r '.tool_name // "<unknown>"' ...)` — 提取工具名（Edit/Write/MultiEdit），jq 不存在时退回 `<jq-missing>` 而不是写空字符串
  3. `FILE=$(... '.tool_input.file_path // "<empty>"' ...)` — 提取文件路径，同样的兜底
  4. `case "$FILE" in "$HOME/accounting-learner/"*) ... ;; esac` — **关键：只在文件路径以 `~/accounting-learner/` 开头时才写日志**。这样即便 hook 是 user 级配置（在所有项目里都触发），也只记录本工作目录的事 —— 不会把你别的项目里的 Edit 操作写进月结日志。
  </Callout>

  <Callout type="warn" title="如果文件已存在，只合并 hooks 部分">
  如果 `settings.local.json` 已经有其他配置（Ch 10 写过），**不要直接覆盖整个文件**。只把 `"hooks": { ... }` 这一段合并进已有的 JSON 对象里。遇到不确定的情况，把文件内容复制给 Claude，说「帮我把这段 hooks 配置合并进去」。
  </Callout>

  ### 测试 hook 真的工作了（不只是「有一行字」）

  配置完成后，打开一个**新的** Claude Code 会话，让它在 `~/accounting-learner/capstone-b/` 下随便建或改一个文件，比如：

  ```
  在 ~/accounting-learner/capstone-b/voucher-gen/ 下创建一个空的 NOTES.md，内容写「测试 hook」
  ```

  然后在另一个终端里检查日志：

  ```bash
  cat ~/accounting-learner/.month-end.log
  ```

  你应该看到类似：

  ```
  [2026-05-22 10:23:45] Write: /Users/你/accounting-learner/capstone-b/voucher-gen/NOTES.md
  ```

  **三项缺一不可**：
  1. 有时间戳
  2. 有工具名（`Write` 或 `Edit` 或 `MultiEdit`，**不是 `<unknown>` 或 `<jq-missing>`**）
  3. 有真实文件路径（**不是 `<empty>` 或 `<jq-missing>`**）

  如果工具名或文件路径出现 `<jq-missing>` → 回到「第 0 步：装 jq」补装一下。

  全部 OK 之后，点「我跑完了」。
</RealStep>

## 6. 运行完整工作流：一句话完成月末结账

这是整个课程的高潮。你将用**一句中文**触发一个完整的四步财务工作流。

在开始之前，确认输入数据就位（至少有一种情况即可）：
- `capstone-a/invoice-ocr/inputs/<period>/` 里有几张发票（PDF 或图片）
- `capstone-a/bank-classifier/inputs/<period>/` 里有银行 CSV 流水文件

`<period>` 就是你想关账的那个月（比如 `2026-05`）。不同月份的文件分子目录放，
**绝对不要混在 `inputs/` 根目录里** —— 否则 aggregator 会把两个月的数据汇总在一起，
5 月报表里就出现 4 月数据。这是月结里最难发现的错。

如果暂时没有真实数据，也没关系——Claude 会在找不到输入文件时停下来告诉你，你可以让它继续或者先放置测试数据。

<RealStep
  id="workflow-run"
  expectsCli="Python3"
  command="cd ~/accounting-learner && claude"
>
  打开终端，进入工作目录启动一个**全新的 Claude Code 会话**：

  ```bash
  cd ~/accounting-learner && claude
  ```

  然后只说这一句话：

  ```
  帮我做本月结账
  ```

  正常情况下，Claude 会：

  1. 识别到 `month-end-close` Skill
  2. 运行第一步：`batch_ocr.py`，告诉你发票 OCR 结果（成功/需手填/失败）
  3. 运行第二步：`bank_classify.py`，展示流水分类统计
  4. 运行第三步：`make_vouchers.py`，生成凭证，告知待核查行数
  5. 运行第四步：`aggregate.py` + 重命名，产出最终文件

  全流程跑完后，检查：

  ```bash
  ls ~/accounting-learner/outputs/
  ```

  应该看到 `month_end_<period>.xlsx`（账期 = 上月，比如今天是 2026-06，文件应叫 `month_end_2026-05.xlsx`）。

  **更关键的检查：看 Claude 最后打印的闭环校验摘要。**
  Skill 跑完之后会输出一段：

  ```
  ===== 月结闭环校验 =====
  会计期间: 2026-05
  凭证总笔数 (vouchers_2026-05.xlsx · 凭证 sheet)  = 78
  银行流水总笔数 (bank_classified_2026-05.csv)     = 81
  待核查笔数 (unmatched_2026-05.csv)               = 3
  校验:  78 + 3 = 81 ✓
  ```

  **判断成功的标准不是『SKILL 跑完了』，而是『最后那行 N + U = M』**。
  如果输出末尾出现 `⚠️ 数字不闭环` —— 文件生成了，但数字不对，**这是『假成功』**，
  必须按下面的恢复清单逐步排查再决定是否封账。

  <Callout type="warn" title="如果 Claude 没有自动识别 Skill">
  可能原因：

  1. **新会话**：确保是全新启动的 `claude`，不是 `--continue` 续上的旧会话。
  2. **SKILL.md 路径**：检查 `~/.claude/skills/month-end-close/SKILL.md` 文件是否真实存在。
     ```bash
     cat ~/.claude/skills/month-end-close/SKILL.md
     ```
  3. **description 措辞**：如果说「做月末结账」没触发，换一句更接近 description 字段措辞的说法，比如「月末结账发票银行汇总」。

  参考 Ch 9 的 Skill 触发排查步骤。
  </Callout>

  <Callout type="tip" title="某一步失败了，怎么办？(简版)">
  Claude 在步骤失败时会展示错误信息并等待你的指示。这是有意设计的——因为 Skill 说明书里写了「遇到错误展示给用户」。

  出错不代表工作流设计有问题——正是因为工作流知道怎么处理错误，才叫「工程化」。
  下面那张表是「**卡在哪一步、单独跑哪条命令、从哪里恢复**」的完整清单。
  </Callout>

  <Callout type="warn" title="恢复清单：卡在哪一步，怎么从中断处恢复（不要从头重跑）">
  四步工作流的好处是：**任何一步失败，都可以单独把那一步跑通，再让 Skill 从下一步继续**。
  不要每次出错就从第一步重跑 —— 重跑 OCR 既慢又会污染已经手填好的「需手填」sheet。

  | 卡在哪一步 | 现象 | 单独重跑命令 | 恢复方式 |
  |---|---|---|---|
  | **第一步 OCR**（`batch_ocr.py`） | 退出码 3/4，或 `invoice_summary_<period>.xlsx` 未生成 | `cd ~/accounting-learner/capstone-a/invoice-ocr && python3 scripts/batch_ocr.py --period 2026-05` | 看具体错误。退出码 4 = 部分识别成功，去打开「需手填」sheet 把空白字段补全，**保存后不要重跑 OCR**，直接让 Skill 从第二步继续 |
  | **第二步 bank-classifier**（`bank_classify.py`） | 编码错误 / 列名找不到 / 输出文件不存在 | `cd ~/accounting-learner/capstone-a/bank-classifier && python3 scripts/bank_classify.py --period 2026-05` | 失败原因常见是 GBK/UTF-8 编码问题（Ch 14 §4 教过），或银行 CSV 列名变了。把报错粘给 Claude 让它修脚本，修完单独跑通这一步，再让 Skill 从第三步继续 |
  | **第三步 voucher-gen**（`make_vouchers.py`） | `unmatched_<period>.csv` 非空 / 「待核查」sheet 非空 | `cd ~/accounting-learner/capstone-b/voucher-gen && python3 scripts/make_vouchers.py --period 2026-05` | 打开 `unmatched_<period>.csv`：每行的「原始分类」就是 `subject_map.py` 里**缺**的标签。手动补进 `DEBIT_MAP` 或 `CREDIT_MAP`，单独重跑 `make_vouchers.py`，确认 unmatched 清零再继续第四步 |
  | **第四步 aggregator**（`aggregate.py`） | `month_end_<period>.xlsx` 里出现非本月数据 / 文件数不对 | 检查 `~/accounting-learner/capstone-a/report-aggregator/inputs/<period>/` 子目录 | 见上面 SKILL.md 的「步骤 0」—— 确认本月文件齐全且只放在 `inputs/<period>/` 子目录里，不要让根目录或其它月份子目录里的 xlsx 混进来。修完直接重跑 aggregator |
  | **hook 日志**（`.month-end.log`） | 没有日志，或文件名出现 `<jq-missing>` / `<empty>` | `cat ~/accounting-learner/.month-end.log \| tail -20` | 看最近的事件。如果一条都没有 → 检查 `settings.local.json` 的 matcher（必须含 `Edit\|Write\|MultiEdit`）；如果出现 `<jq-missing>` → 回 §5 第 0 步装 jq；如果文件路径不是 `~/accounting-learner/...` → 检查 case 语句的路径前缀 |
  | **闭环校验不通过**（`N + U ≠ M`） | 末尾红字提示 `⚠️ 数字不闭环` | 不要急着封账 | 大概率是「待核查」sheet 或 unmatched.csv 没处理完。回到第三步的恢复方式，逐笔补完，再单独重跑 `make_vouchers.py` 和闭环校验脚本（不需要重跑 OCR 和 bank-classifier） |

  **通用原则**：每一步的输出都是磁盘文件，不是内存状态。任何时刻你都可以「只重跑出错的那一步」，
  前面已经成功的文件继续用。这就是 Ch 14 把工具拆成三个独立目录的回报 —— 现在你可以从任意一步恢复。
  </Callout>

  看到最终输出文件、并且 Claude 报告 `N + U = M` 闭环校验通过之后，点「我跑完了」。
  如果闭环校验不通过，先按上面的清单把数字补对，再来点这个按钮。
</RealStep>
