## 1. 为什么要认识第三种工具？

到目前为止你已经有了两位 AI 同事：

- **Claude Code**——对话探索型，喜欢先确认再动手
- **Codex CLI**——批量执行型，接到任务就开干，完成后汇报

第 13 章介绍 **Cursor**。不过，在开始之前，有一点非常重要：

> **Cursor 不是"你的新编辑器"。**

作为一个从来没有写过代码的会计，你不需要学习一个新的代码编辑器。你需要的是：**Cursor 里的三个特定工作流**——它们能做到 Claude Code 和 Codex CLI 在终端里做不到的事。

这三个工作流是：

| 功能 | 一句话描述 |
|---|---|
| **Composer** | 一次 prompt 修改多个文件，AI 帮你在项目里"到处跑" |
| **@ 引用** | 输入 `@` 精准定位文件/函数，不需要先解释你的项目结构 |
| **Background Agent** | 把耗时任务交给 Cursor 异步跑，你去喝茶，它做完通知你 |

学完这三个工作流，你就掌握了 Cursor 的核心价值。其余的编辑器功能，可以忽略。

## 2. 安装 Cursor 并配置 CLI

<RealStep
  id="cursor-installed"
  expectsCli="Cursor"
  command="cursor --version"
>
  **第一步：下载并安装 Cursor**

  打开 [cursor.com](https://cursor.com)，点击下载按钮，安装 macOS 版本的 Cursor.app。

  **或者**，如果你更习惯 Homebrew：

  ```bash
  brew install --cask cursor
  ```

  **第二步：把 `cursor` 命令安装到终端**

  Cursor 装好之后，还需要一步才能在终端里用 `cursor` 命令：

  1. 打开 Cursor.app
  2. 按 `Cmd+Shift+P` 打开命令面板
  3. 输入 **"Install 'cursor' command"**，回车确认

  这会把 `cursor` CLI 安装到你的 PATH 里。完成后在终端里验证：

  ```bash
  cursor --version
  ```

  你会看到类似 `Cursor 0.x.x` 的版本号。

  <Callout type="warn" title="点 'Install command' 时会弹 macOS 系统密码框——不是病毒">
  点完 "Install 'cursor' command" 之后，屏幕上会弹一个**灰底白字的小窗口**，左侧是 Terminal 图标，写着「Terminal wants to make changes」之类的字样，要求你输入密码。

  **这不是病毒**——Cursor 在帮你装一个 `cursor` 命令到 `/usr/local/bin/` 或 `/opt/homebrew/bin/`，这两个目录是 macOS 的系统级目录，**任何 App 往这里写文件都需要你的电脑开机密码授权**（这是 macOS 自己的保护机制，不是 Cursor 的）。

  **怎么做**：输你的**电脑开机密码**（不是 Cursor 账号密码、不是 Apple ID），回车。屏幕上**不会显示星号或圆点**，但你的输入是收到的——闷头打完密码、按回车就行。

  完成后命令面板会显示成功提示。如果你输错了密码，会再弹一次让你重试。
  </Callout>

  <Callout type="tip" title="找不到「Install 'cursor' command」？">
  在命令面板里搜索 "shell command" 或 "install cursor"，不同版本的 Cursor 菜单文字可能略有差异。或者在菜单栏找 **Cursor → Install 'cursor' command**。
  </Callout>

  <Callout type="warn" title="必做：第一次启动 Cursor 后，先开 Privacy Mode（再做任何任务）">
  **路径：Settings → General → Privacy Mode → Enabled。**

  **为什么必须开**：Cursor 个人账号（Hobby / Pro）默认 **不开** Privacy Mode——这意味着你和 AI 的对话内容、代码片段、提示词，**默认会被上传到 Cursor 服务器**，可能用于改进他们的模型。
  （Team / Enterprise 账号才默认开启 Privacy Mode；个人账号需要自己手动打开。来源：[cursor.com/data-use](https://cursor.com/data-use)，2026-05 核对）

  对一个 **10 年财务的会计** 来说，这是不能接受的：`~/accounting-learner/` 里会有客户姓名、银行卡号、税号、金额。这些数据 **不应该** 进任何 AI 公司的训练管道。

  开启 Privacy Mode 后：
  - 你的代码不会被 Cursor 用于训练模型
  - Cursor 与各个模型供应商（Anthropic、OpenAI 等）也维持零数据保留协议

  **在做下一步登录 / 第 4 节的第一次 Composer 任务之前，先把这一步做了。** 验证方式：Settings → General → Privacy Mode 显示已勾选 / Enabled。
  </Callout>

  看到版本号、并已开启 Privacy Mode 之后，点「我跑完了」。
</RealStep>

## 4. Cursor 超能力一：Composer——一次改多个文件

**Composer 是 Cursor 最重要的功能**，也是它与 Claude Code / Codex CLI 最大的区别：你给它一个跨越多个文件的任务，它会同时打开、修改多个文件，统一处理。

在终端里，Claude Code 和 Codex 也能修改多文件——但 Cursor Composer 的优势在于：你可以在图形界面里**看到每个文件的改动、逐个接受或拒绝**，同时保持整个任务上下文完整。

### 典型使用场景（真实会计版）

你在 Ch 7 写的 `scripts/invoice_ocr.py` 当前只处理人民币（CNY）发票——如果客户给的是美元、欧元、港币发票，脚本会出错（CSV 里 `amount` 字段会变成混着不同币种的数字，加总出来的"总金额"毫无意义）。

让 Composer 帮你给这个脚本加币种支持：(a) 从 OCR 提取 `currency` 字段；(b) CSV 输出多一列 `currency`；(c) 不认识的币种回退到 `CNY` 并打印警告。

<RealStep
  id="composer-tried"
  command="cursor ~/accounting-learner"
>
  **第一步：先做 Git 快照**（重要）

  在终端里：

  ```bash
  cd ~/accounting-learner && git add -A && git commit -m "snapshot before cursor composer"
  ```

  这一步和 Ch 12 用 `codex exec` 之前的快照纪律是一样的——Composer 改坏了，`git restore .` 一条命令回滚。

  **第二步：在终端里用 Cursor 打开你的工作目录**

  ```bash
  cursor ~/accounting-learner
  ```

  或者在 Cursor.app 里通过 **File → Open Folder** 打开 `~/accounting-learner`。

  **第三步：打开 Composer**

  按 `Cmd+Shift+P`，搜索 **"Open Composer"**，回车。

  （Composer 的快捷键在不同版本可能是 `Cmd+I` 或 `Cmd+K`——用命令面板最保险。）

  **第四步：给 Composer 这个跨文件任务**

  在 Composer 输入框里输入：

  ```
  请帮我修改 scripts/invoice_ocr.py 这个脚本，给它加上多币种支持。

  当前问题：脚本只处理人民币（CNY）发票。如果发票是 USD/EUR/HKD，
  CSV 输出里看不出币种，加总出来的金额没意义。

  需要做三件事：
  1. 从 OCR 返回的 JSON 里读取 fields.amount.currency 字段
     （这个字段 aa-ocr 已经在输出里给出了，例如 "CNY"、"USD"）
  2. CSV 输出里新增一列 "currency"，放在 "amount" 列后面
  3. 如果 currency 不在 ["CNY", "USD", "EUR", "HKD", "JPY"] 这五个里，
     回退到 "CNY" 并 print 一行警告：
     [警告] 发票 {文件名} 的币种 {未知值} 不在已知列表，按 CNY 处理

  改完后请同时检查脚本里所有写 CSV 表头的地方都同步更新，
  确保新旧 CSV 字段对齐。
  ```

  按回车。**观察 Composer 的行为**：它会同时展示 `scripts/invoice_ocr.py` 里多处改动（读 JSON 的地方、写 CSV 表头的地方、写 CSV 行的地方、新增的警告分支）——你可以逐个文件 / 逐个 diff Accept 或 Reject。

  这就是 Composer 相对终端 AI 的核心价值：**多处相关改动一次性、图形化、可逐项审阅**。

  <Callout type="tip" title="scripts/invoice_ocr.py 不存在？">
  如果你跳过了 Ch 7、`scripts/invoice_ocr.py` 还没创建——退而求其次：在 Composer 输入框里把任务改成"**挑 `~/accounting-learner/scripts/` 里随便一个 Python 文件，加一个 `--verbose` 命令行参数，开了之后多打印几行调试信息**"。重点是体验 Composer 同时展示多处改动 + 逐项接受/拒绝的工作流，具体任务不重要。
  </Callout>

  接受 / 拒绝完所有改动、看到脚本最终改完之后，点「我跑完了」。
</RealStep>

## 5. Cursor 超能力二：@ 引用——精准锁定上下文

**@ 引用解决了一个日常烦恼**：每次开始一个新对话，你都要花时间解释"我的项目里有个 xxx 文件，它是用来做 yyy 的"……这很烦。

在 Cursor 里，输入 `@` 就会弹出文件/函数选择器。你直接把文件"喂"给 AI，它立刻知道你在说哪个文件的哪个部分，不需要你解释项目结构。

<RealStep
  id="at-ref-tried"
  command="cursor ~/accounting-learner"
>
  在 Cursor 的对话框（Chat，`Cmd+L`）或 Composer 输入框里，输入 `@`。

  你会看到一个下拉列表，列出了你工作目录里的文件。

  ### 真实任务：让 Cursor 给你的脚本写一份接手说明

  你刚给 `invoice_ocr.py` 加了币种支持（上一步 Composer 改完的）。现在假设你下周休假，要把这个脚本交给同事接手——同事需要一份**简短的中文说明**，告诉他这脚本是干嘛的、怎么跑、怎么改字段。

  自己写很慢，而且你写不清楚脚本里所有的细节。让 Cursor 帮你写。

  在 Chat 输入框里输入：

  ```
  @scripts/invoice_ocr.py @CLAUDE.md
  请基于这两份文件，给我写一份 5–8 行的 README，
  放在 scripts/invoice_ocr.README.md。
  目标读者：一个第一次接手这个脚本的会计同事。
  必须涵盖：
  - 这个脚本是干嘛的（一句话）
  - 怎么跑（一行命令示例）
  - 输入是什么、输出是什么
  - 想改提取字段（例如加发票号）该改哪一段
  用中文写，不要写代码注释那种风格，要写给"人"看。
  ```

  按回车。**观察 @ 引用的效果**：
  - Cursor 不需要你先解释"我有个脚本叫 invoice_ocr.py，它的作用是……"——你 @ 进去它直接读了
  - 同时 @ 了 `CLAUDE.md`，Cursor 也知道整个项目的上下文（数据隐私底线、目录约定等），写出来的 README 会跟项目风格一致
  - 输出的 README 是基于**真实代码内容**的，不是 Cursor 凭空猜的

  <Callout type="insight" title="@ 引用的本质">
  @ 引用做的事，和你手动把文件内容复制粘贴给 AI 是一样的——只不过 Cursor 帮你自动化了这个步骤。
  真正有价值的是：**你可以 @ 一个函数、一个类、甚至一个文档链接**，不只是文件。这让你可以非常精准地控制 AI 看到的上下文范围。

  在会计工作里 @ 引用最常见的两种用法：
  - **接手 / 交接**：`@这个脚本 @这份说明 给同事写份 README`
  - **跨文件理解**：`@invoice_ocr.py @batch_ocr.py 这两个脚本是什么关系？哪些函数在做相同的事？`（避免重复代码）
  </Callout>

  <Callout type="tip" title="invoice_ocr.py 或 CLAUDE.md 不存在？">
  跳过了前面章节的话，@ 任何一个 `scripts/` 下的 `.py` 文件都行，prompt 改成"用中文给这份脚本写一份 5 行 README"即可。重点是体验 @ 直接喂文件给 AI、跳过手动解释项目结构这一步的工作流。
  </Callout>

  生成出 README 文件（不管 Cursor 是直接写文件还是把内容贴在 chat 里让你自己保存）、看到内容基于真实代码而不是泛泛而谈之后，点「我跑完了」。
</RealStep>

## 6. Cursor 超能力三：Background Agent——异步任务，但跑在云端

**Background Agent 是 Cursor 与 Claude Code / Codex 最本质的差异**：

- Claude Code 和 Codex CLI 是**同步的**——你在终端里等它跑完，期间做不了别的
- Cursor Background Agent 是**异步的**——你把任务交给它，它独立跑完后通知你，你可以同时做别的

但是——这里有一个**很多人会误解的关键点**：

<Callout type="warn" title="Background Agent 不是「本地后台进程」——它跑在 Cursor 的云端服务器上">
"Background" 这个词容易让人以为它是 macOS 里那种"后台运行"的 App。**不是。**

Background Agent 的真实运作方式（来源：[Cursor Cloud Agent 文档](https://cursor.com/docs/cloud-agent) + 第三方分析，2026-05 核对）：

1. **它跑在 Cursor 公司的云端服务器**（Docker 容器 + AWS VM），**不是你的电脑**。
2. **要求把你的代码仓库挂到 GitHub**——Background Agent 从 GitHub clone 你的仓库到云端容器里执行。
3. **Cursor 在云端 fork 出一个临时分支**（ephemeral checkout）跑任务，跑完后把改动 push 回你的 GitHub 仓库（通常以 PR 形式）。
4. **你关掉 Cursor.app 它还在跑**——因为它根本不在你本机。
5. **代码 + 上下文 + 模型调用全部发生在 Cursor 控制的环境里。**

**对会计场景来说，意味着什么？**

`~/accounting-learner/` 里有客户姓名、银行卡号、税号、金额——这些数据 **不应该** 被 push 到 GitHub，更不应该被任何第三方云容器读取。

**所以：本章 §6 只让你认识 Background Agent 是什么、能做什么——不建议你把会计真实数据交给它跑。** 对于敏感数据，本地 Composer + Privacy Mode 已经够用。

如果你以后用 Background Agent 处理 **不含真实客户数据的代码**（例如开源工具、个人脚本），它确实能帮你省时间。但别忘了它的真实模型：**云端代理 + GitHub 仓库 + 临时分支**。
</Callout>

<RealStep
  id="background-agent-tried"
>
  **认识 Background Agent 的入口：**

  在 Cursor 里，通过 `Cmd+Shift+P` 搜索 **"Background Agent"**，或在侧边栏找到对应入口（不同版本界面可能略有差异）。

  **方案 A（推荐做法 —— 只读演示，不提交真实数据）：**

  打开 Background Agent 面板，**只观察它要求你做什么**：通常会要求连接 GitHub、选择仓库、配置 Dockerfile / 环境、授权 push 回 GitHub 等。**看到这些权限请求就够了**——它在向你坦白"我需要把你的代码 clone 到云端，跑完再 push 回 GitHub"。

  如果你想再多看一步，但**不实际上传任何真实数据**：用一个**全新的空 GitHub 仓库**（或者你自己之前建的纯学习仓库，里面只有几个 `print("hello")` 的 Python 文件）做演示，给 Background Agent 一个最简单的任务：

  ```
  Add a hello.py that prints "Hello from Background Agent".
  ```

  看 Background Agent 会问你什么权限（GitHub 授权、仓库选择、是否允许它创建 PR 等）、跑完之后它会以什么方式把结果交付给你（通常是 GitHub 上的一个新 PR）。**整个过程你的真实会计数据完全没出现过**——演示完就关掉这个仓库。

  **方案 B（除非你完全清楚自己在做什么，否则不要走这条路）：**

  即使你是 Pro 账号、即使有完整 Privacy Mode，也**不要**把 `~/accounting-learner/` 直接挂到 Background Agent——因为这个目录里的真实客户姓名、银行卡号、税号、金额会被 Cursor clone 到云端 Docker 容器、走过 GitHub。Privacy Mode 管的是"不被用来训练模型"，**不管"数据是否离开你电脑"**。这两件事不一样。

  <Callout type="insight" title="异步代理 vs 本地工具——不是更聪明，是更远">
  Background Agent 和 Claude Code / Codex 的区别不是智能程度——而是：
  - **工作节奏**：异步 vs 同步
  - **数据物理位置**：云端 vs 本机
  - **触达范围**：GitHub 仓库 vs 本机文件夹

  对会计场景：**本机数据 → 本地 Composer 更稳**。云端代理留给开源代码 / 公开数据这类不敏感的任务。
  </Callout>

  <Callout type="warn" title="Hobby 免费用户：怎么判断这一步算「学完」">
  Background Agent **从 Cursor Pro（$20/月）档位开始包含**，免费 Hobby 不包含。

  **Hobby 用户跳过实操的判据：** 你读完了上面的 Background Agent 云端架构警告（云端 Docker 容器 + GitHub 仓库 + 临时分支）+ §2 的 Privacy Mode 已经在你的 Cursor 里开了 → 这一步的学习目标已达成，直接点「我跑完了」。**这不是放弃，这是"知道工具的边界在哪"——比真去跑一次更重要**。
  </Callout>

  <Callout type="tip" title="你不是 Hobby，但点 Background Agent 入口完全没反应？">
  按这个顺序排查：
  1. 看 Cursor 应用**左下角**——是不是显示已登录状态（账号邮箱可见）？没登录的话回 §3。
  2. 打开 **Settings → Cursor Subscription**（或 Account 页面），确认订阅状态是 Pro 或更高，没有过期。
  3. 试用期刚结束、订阅还没续 → 入口会灰掉或提示升级，不是 bug。
  4. 都正常但还是不行 → 命令面板搜 "Background" 多关键词试，不同版本入口名可能略有差异（"Background Agent" / "Cloud Agent" / "Agent"）。
  </Callout>

  观察了 Background Agent 的入口、并理解了"云端代理"的真实模型之后，点「我跑完了」。

## 7. Part IV 综合：三工具该怎么选？

你现在有了三位 AI 同事。这是 **Part IV 的核心收获**：知道什么时候该叫哪位出马。

<RealStep
  id="tool-choice-understood"
>
  仔细读完下面的三工具对比表，对照自己过去几章的操作体验，形成你自己的判断框架。

  ---

  ### 三工具对比：Claude Code vs Codex CLI vs Cursor

  | 维度 | Claude Code | Codex CLI | Cursor |
  |---|---|---|---|
  | **界面** | 终端（纯文字） | 终端（纯文字） | GUI + 终端 |
  | **工作节奏** | 同步，喜欢先确认 | 同步，直接动手 | 同步 or 异步（Background Agent） |
  | **多文件处理** | 可以，但逐个确认 | 可以，批量自动 | Composer：图形化多文件审阅 |
  | **上下文引用** | 手动粘贴或 SKILL.md | 手动描述 | @ 引用，精准一键 |
  | **异步任务** | 不支持 | 不支持 | Background Agent（**云端代理**，需 Pro） |
  | **数据位置** | 本机 | 本机 | Composer 本机；Background Agent **在 Cursor 云端 + GitHub** |
  | **适合场景** | 探索性对话、边想边做 | 明确的批量文件操作 | 多文件项目编辑（本地）；异步任务（非敏感数据） |
  | **隐私要点** | 视 Anthropic 账号策略 | 视 OpenAI 账号策略 | **个人档需手动开 Privacy Mode**；Background Agent 走云端 |
  | **订阅要求** | Anthropic 账号（Claude Pro / Max 等） | 包含在 ChatGPT 免费 / Plus / Pro 等各档位（详见 [openai.com/chatgpt/pricing](https://openai.com/chatgpt/pricing)） | Cursor Hobby（免费）/ Pro $20/月 / Pro+ $60/月 / Ultra $200/月（Background Agent 需 Pro 起） |

  ---

  ### 实际工作里的选择逻辑

  **用 Claude Code，当你：**
  - 还不确定任务的方向，需要边聊边想
  - 任务比较敏感，想在每一步确认后再继续
  - 在终端里工作，不想切换到 GUI

  **用 Codex CLI，当你：**
  - 任务非常明确（比如：把 data/raw/ 里所有 CSV 分类）
  - 需要批量处理大量文件，不想逐个确认
  - 提前做了 Git 快照，可以放心让它自动跑

  **用 Cursor，当你：**
  - 需要同时修改多个文件，并想逐个文件审阅改动
  - 想用 @ 快速给 AI 提供精准的文件上下文，省掉解释步骤
  - 任务耗时较长，可以交给 Background Agent 异步处理，自己去做别的

  ---

  <Callout type="warn" title="回顾 Ch 12 Codex 的 Git 快照纪律——同样适用于 Cursor">
  Ch 12 §2 教过：用 `codex exec` 自动审批模式之前，先 `git add -A && git commit -m "snapshot before ..."`——这是你唯一的"撤销键"。

  **这条规则对 Cursor Composer 同样成立，甚至更重要**：
  - Composer 一次跨多个文件改动，影响面比 Codex 一次任务更大。
  - Codex CLI 还有 `--sandbox` 标志可以限制写权限——**Cursor 没有等价的 `--sandbox`**，你的 Git 快照就是它的唯一"撤销"按钮。
  - 改完发现 Composer 把脚本搞坏了？`git restore .` 一条命令，回到快照那一刻。没快照 = 没退路。

  所以：**每次 Composer 跑批量改动前，先在终端做一次 `git add -A && git commit -m "snapshot before cursor batch"`**。养成这个肌肉记忆，三个 AI 工具都受益。
  </Callout>

  ---

  <Callout type="insight" title="没有「最好的工具」——只有「合适的工具」">
  这三个工具背后的 AI 模型能力相近，但**工作流设计完全不同**。

  一个有经验的 AI 辅助会计工作者，会根据任务性质在三者之间灵活切换——就像一个有经验的厨师，不会只用一把刀切所有食材。

  你现在已经有了全套工具箱。接下来的第 14、15 章，我们用一个完整的毕业项目来把这些工具串起来。
  </Callout>

  读完对比表、形成了自己的判断框架之后，点「我跑完了」。
</RealStep>
